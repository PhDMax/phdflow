## Session summary — v0.24.2 (June 2026)

### Released
PhDFlow v0.24.2 — release script fix (changelog generation).

### Changes this session

#### Fixed: release notes included entire project history
`scripts/release.mjs`'s `gitLogSinceLastTag()` used
`git describe --tags --abbrev=0` to find the previous version's tag. GitHub
releases create tags **remotely** via the API, but the local repo never ran
`git fetch --tags`, so its newest known tag was stale (`v0.9.0`). The
resulting "Changes" section in the v0.24.1 release notes pulled in ~15
versions of history instead of just the one commit since v0.24.0.

Fixed by having `gitLogSinceLastTag(oldVersion)`:
1. Run `git fetch --tags` first, so newly-created remote tags are visible
   locally.
2. Diff directly against `v${oldVersion}` (read from `package.json` before
   bumping) instead of relying on `git describe`.

The v0.24.1 release notes were also corrected via the GitHub API
(`PATCH /releases/{id}`). Verified the fix on this v0.24.2 release — the
changelog now correctly shows only the commits since v0.24.1.

### Standard release process (now five steps + verification)
1. `node scripts/release.mjs [patch|minor|major]`
2. Update wiki pages for any new/changed views
3. `node scripts/wiki-push.mjs`
4. Update this file (`CLAUDE.md.txt`) with a session summary, then
   `node scripts/push.mjs`
5. Verify `CLAUDE.md.txt` and any changed wiki pages match what's live on
   GitHub (`curl raw.githubusercontent.com/...` + diff — `gh` CLI is not
   available in this environment)
6. Check the GitHub release page (via the API, using the token from `.env`)
   for correct title, changelog, and all 8 assets
